# 低配额接力（默认关闭）

G-Hub 顶部圆环下方和 Manager 概览均有开关。首次启用需要用户操作；关闭时不会发起路由配额探测、切号或续发。

## 规则

只有原生 DOM 显示任务正在运行时，G-Hub 才提交任务观察。后端最多每 20 秒读取一次账号配额，按当前选中模型识别 Gemini / Claude+GPT 池；也可在设置中指定池。模型未知时寻找确实低配额的已知池。

当前账号实时的 5h 或周配额 **≤5%** 时，选择同池 5h 和周配额均已知、均 **>5%**、且本机保险库凭据可恢复的账号。按两个窗口中较小的剩余额度排序，优先余量最大的账号。缓存、未知或超过 90 秒的采样不触发切号。

切号成功后至少间隔 120 秒再路由，失败候选暂缓 10 分钟。没有候选时显示原因，不凭空判定冷却或造配额。手动切号使尚未开始的自动决策失效；正在切号或续发时拒绝另一条手动切号请求。

## 接续任务

1. 读取真实加载的消息、原会话 ID、当前模型和可用项目元数据。
2. 必须有已加载的用户指令，或用户为当前会话保存的「接力备忘」。不把助手进度当成任务目标。
3. 工作目录来自真实宿主属性、当前账号的 workspaceStorage 元数据或用户明确填写的绝对目录。已有项目名称却无法确定目录时暂停，提示填写，不把名称伪装成路径。
4. 先将任务交接写入 `~/.2ag/workspace/relay.json`，再进入切号事务；保存失败不切号。
5. 切号前再次确认开关、原账号、任务是否仍运行、会话是否变化和观察是否过期。
6. 目标身份核对后，在新宿主尝试打开原会话；不可用时使用新会话，将原始加载消息与备忘作为本地文本交接。保留模型，恢复工作目录，不调用模型总结上下文。
7. 等待原生输入区可写，用原生编辑与发送按钮续发。不会清除 disabled 强发，不覆盖用户未发送的输入，也不打断已运行的原生任务。
8. 每份交接带独立 ID；观察到对应的新用户消息才标记「已接收」。点击过按钮但结果不确定时保留交接、阻止自动重发，需用户查看原生会话后确认。

交接可复制、恢复或丢弃；本地保留最近 20 条接力事件。备忘绑定原会话，避免套用到下一项任务。进程重启后，未完成交接暂停；不能把上次未确认的发送重新当成未发送。

## 切号纠错

- 已是目标账号且宿主存活时核验原生登录与新 access token，成功后不重启，也不以旧保险库覆盖最新 token。没有宿主时仍需启动与验证。
- 停止后再读取并归档宿主最后刷新过的凭据，写入目标前保存 DPAPI 恢复记录。
- 凭据写入、宿主启动或身份核对失败均进入恢复路径；恢复宿主失败不能报告完整回滚成功。
- 原来未登录时恢复空身份，不再从失败目标的主控记录中自动找回该账号。
- 可恢复凭据与 Broker 新登录的判定分开：归档 ID token 到期不等于 refresh 登录材料无效。真实刷新仍由原生宿主负责，路由容量仍必须有实时证据。
- 增强启动在账号凭据失败时阻断；变更 API 请求不跨端口重试，防止一次点击产生两次操作。

## API

- `GET /api/v1/accounts/relay`：开关、状态、候选、记录和交接元信息。
- `POST /api/v1/accounts/relay`：保存 `enabled`、`pool`、`workspace_path`、`task_brief`、`brief_conversation`；或执行 `retry`、`dismiss`、`confirm-running`、`confirm-not-sent`。
- `POST /api/v1/accounts/relay/pulse`：真实原生任务观察，不接受配额数字作为路由依据。
- `GET /api/v1/accounts/relay/handoff`：复制保留的交接正文。
- `POST /api/v1/accounts/relay/handoff`：带交接 ID 更新原生续发阶段；领取时必须携带独立 `claim_id` 并核对目标身份。只有领取者可以确认或释放该次发送，另一窗口的失败不得清空它。

数据为本地 JSON，包含任务文本与元信息，不含登录凭据。Windows 账号事务使用现有跨进程凭据锁和 DPAPI 保险库。

## 本轮证据与边界

2026-10-03 的后续任务明确授权必要测试、构建和实机验证。账号事务已真实复现归档过期误判、原生资格拒绝与回滚；同账号切换核验有效且未重启。接力发送领取的并发所有权回归测试通过；代码已加入本地构建。

**未进行真实任务耗尽配额后的端到端接力**，因为本轮没有满足阈值的可用任务与候选；没有用伪造配额或模拟状态冒充实机体验。宿主 DOM 改版、未加载历史指令、目录无法识别、模型选择或原生接收未观察到时，会暂缓并保留可处理的信息。

没有自动总结、云同步、多模型调度、任务调度器或通用故障恢复平台。
